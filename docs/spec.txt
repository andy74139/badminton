一、架構與檔案責任

靜態網站，不引入後端、資料庫、框架或建置流程。以一般 <script> 載入，依序 roster.js → pairing.js → index.html 內嵌主程式；模組以 IIFE 掛在 window.Roster / window.Pairing，並同時支援 Node 的 module.exports（供 tests/run.js 使用）。

- index.html：介面、事件掛接、DOM render，以及狀態協調：load/save、startAll、proposeCourt、regenerateCourt、confirmCourt、完賽、resetCounts、setCourtCount、刪除成員後補位、連結/分開雙人組、匯入對話框。
- roster.js：預設名單 DEFAULT_GROUPS、ensureStateFields、createDefaultState、availableGroups、姓名正規化、人員設定檔、貼上名單解析 parsePaste、applyImport、normalizeSeats、addGroup/addMemberToGroup/removeMember、migrateV1/migrateV2。
- pairing.js：SCORE 常數、平均值與有效場數、個人分數、性別/實力分數、可用人員收集、組合列舉、pickBestCourtCombo、scoredManualCandidates、pickFillCandidate、setResting/toggleResting、setRestCompensationEnabled、displayStats。純函數為主，不操作 DOM 或 localStorage。pairing.js 透過 global.Roster.availableGroups 取得可用組別（執行時才呼叫，避免載入順序相依）。

註：index.html 仍留有未使用的舊版函式（見 K-08），修改時以 Roster/Pairing 模組為準。

二、資料模型

1. 本場狀態（localStorage key：badminton_rotation_v3）

state = {
  schemaVersion: 3,
  nextGroupId: number,
  nextMemberId: number,
  groups: [{ id, memberIds: [memberId, ...], type: "single" | "rotate" | "fixed" }],
  members: {
    [memberId]: {
      id: number,
      name: string,
      groupId: number,
      playCount: number,              // 本場實際上場次數
      onCourt: "A" | "B" | "C" | null,// 在哪個場地（含待確認名單）
      gender: "M" | "F" | null,
      skill: 1 | 2 | 3 | null,
      resting: boolean,               // 臨時不打
      lastFinishedAt: number | null,  // epoch ms，由「完賽，換下一組」記錄
      restCreditTotal: number,        // 已結算不打場數（含新人起始補償）
      restStartAverage: number | null // 目前不打期間的基準平均
    }
  },
  groupCounts: { [groupId]: number },   // 組別輪替次數；僅顯示/相容用，不參與新演算法
  courts: { A: [seat|null x4], B: [...], C: [...] },  // seat = { groupId, memberId }
  pending: { A: boolean, B: boolean, C: boolean },    // true = 待確認名單
  pendingRejectedMemberIds: [memberId, ...],          // 「再換另一批」暫時扣分名單（全場地共用）
  courtCount: 1 | 2 | 3,
  started: boolean,
  settings: { restCompensationEnabled: boolean },     // 預設 true
  profiles: { [normalizedName]: { name, gender, skill } }
}

組別類型：
- single：一位成員。
- rotate：兩位成員共用一個名額，同時最多一人上場。
- fixed：兩位成員必須同時上場且同隊。
新增單人 → single；新增雙人組 → rotate；addMemberToGroup 會把 single 改為 rotate；「分開」後兩組皆為 single；「連結」依使用者選擇 fixed（預設）或 rotate；removeMember 後只剩一人的組別改為 single；貼上名單依格式為 single / rotate / fixed。
ensureStateFields 對缺少 type 的組別補 "single"；migrateV2 補 "rotate"（見 K-06）。

2. 次數定義

- playCount：真正上場次數。pending 建議名單不計次；confirmCourt 時對該場實際入座者各 +1；已確認場地手動換人時，新入場者立即 +1。
- restCreditTotal：已結算的不打場數，以及新增成員時給予的起始補償。
- activeRestCredit(member, avgActual, enabled)：目前不打期間已達成的補償。
- effectivePlayCount(member, state)：
    開關開啟：playCount + restCreditTotal + activeRestCredit
    開關關閉：playCount（restCreditTotal 保留於資料但不計入）
- avgActualPlayCount(state)：姓名非空白且 resting !== true 的成員 playCount 平均；沒有則 0。
- avgEffectivePlayCount(state)：同一群人的 effectivePlayCount 平均。用於個人公平分數與新人起始補償。
- 不打場數基準只用 avgActualPlayCount，避免補償推升平均造成回饋循環。

3. 人員設定檔

- normalizeName(name)：trim → NFKC → 連續空白合併為一個 → trim → 轉小寫。
- ensureProfiles：profiles 為空時由目前 members 建立；否則補上 members 中有但 profiles 沒有的姓名（不覆蓋既有）。
- syncProfile(state, member)：以 member 目前的姓名/性別/實力覆寫該姓名的 profile。UI 在性別、實力切換及姓名 blur 時呼叫；臨時不打切換時也會呼叫。
- profiles 不會因成員刪除而刪除；只有在過去名單按刪除並確認（Roster.deleteProfile）時才刪除。
- 手動映射至他人的舊設定時，把舊設定的性別/實力複製到新姓名的 profile；不複製 playCount、lastFinishedAt、restCreditTotal。

三、貼上名單解析及匯入

1. parsePaste(text) → { ok, errors, warnings, people, groups, lines }
   - 以換行切割，忽略空白行；全空白 → 錯誤「請輸入名單」。
   - 每行以 "/" 切割並 trim。若最後一段為 FIXED_MARKERS（「[固定]」「(固定)」「【固定】」）之一，先移除該段並記為 "fixed"，再檢查：
       超過兩段 → 錯誤「第 N 行超過兩個成員」；
       沒有段或有空段 → 錯誤「第 N 行有空姓名」；
       fixed 但不是兩段 → 錯誤「第 N 行固定雙人組需要兩位成員」。
     有任何格式錯誤即回傳，不產生 people/groups。
   - 類型：有標記 → "fixed"；否則一人 → "single"，兩人 → "rotate"。存於 lines[i].type 與 groups[i].type。
   - groups[i] = { index, names, type, personIndexes }；people[j] = { name, normalizedName, index }。
   - 正規化後重名：同時加入 warnings 與 errors（「重複姓名：X」），ok=false。
2. attachSuggestedProfiles(state, parsed)：為每位 person 設定 suggestedProfile = 同正規化姓名的 profile key 或 null。
3. 預覽 UI（輸入即時更新）：錯誤（紅字）、警告、「解析出 N 組・M 人」、每人一列姓名＋下拉選單（"__none__" 不套用舊設定 + 全部 profiles，顯示姓名（性別／實力）），預設值為 suggestedProfile。有錯誤時「確認匯入」停用。
4. applyImport(state, parsed, mode, selections, now)
   selections[i]：profile key、"__none__"（不套用）或 undefined（使用 suggestedProfile）。
   A. mode = "new"（開始新場次）
      - 依匯入名單建立新 groups/members，ID 從目前 nextGroupId / nextMemberId 接續。
      - 每人：playCount=0、restCreditTotal=0、lastFinishedAt=null、onCourt=null、resting=false、restStartAverage=null；性別/實力取自所選 profile（無則 null），並寫回該姓名 profile。
      - groupCounts 全 0；courts 清空、pending 全 false、started=false。
      - 保留 profiles、courtCount、settings。
   B. mode = "update"（更新目前場次）
      - 以正規化姓名對應目前既有成員（同名多筆時依序取未使用者），沿用原 member 物件：保留 playCount、restCreditTotal、lastFinishedAt、resting、restStartAverage、onCourt；若有選定 profile 則套用其性別/實力。
      - 新成員：playCount=0、restCreditTotal = round(avgEffectivePlayCount×2)/2（開關開啟時，否則 0）。
      - 所有組別重新配發新 ID，type 依匯入；新組別 groupCounts=0，已不存在的組別 groupCounts 刪除。
      - 刪除未出現在匯入名單中的成員（profiles 保留）。
      - 套用新 groups/members 後呼叫 normalizeSeats(state)（見下方 5.）：留下的人保留座位並改用新 groupId，被移除者的座位清空，onCourt 依座位重建。
      - 不改 started 與 pending；index.html 在 applyImport 成功後呼叫 refillEmptySeatsIfStarted 補空位（見六）。
   C. 匯入對話框說明文字與 placeholder 列出單人、雙人輪流、固定雙人組三種寫法。
   D. 原子性：parse 與預覽不改 state；按「確認匯入」後才呼叫 applyImport 並 save。取消或點背景關閉不做任何修改。
5. normalizeSeats(state)（roster.js，匯入更新、linkMembers、splitPair 後與 load 時呼叫）
   a. 對 A/B/C 每個座位：成員不存在、其 groupId 對應的組別不存在、或此人已出現在前面的座位 → null；否則 seat.groupId 改為 member.groupId。
   b. 不檢查組別規則（同組多人在場上、固定組不同隊）：目前配隊保留，組別規則只在之後選人時套用。
   c. 所有成員 onCourt=null，再依座位設定 onCourt。

四、可用人選與候選列舉（規則見 requirements ALG-02、ALG-03）

1. Roster.availableGroups(state)
   - fixed：每位成員都存在、不在場上、姓名非空白、未臨時不打，整組才可用。
   - single / rotate：所有成員都不在場上且姓名非空白，並且至少一位未臨時不打，才可用。
     （任一成員在任何場地上，包括待確認名單，整組不可用 → 同組兩人不會跨場。）
2. Pairing.collectAvailablePersons(state)：對每個可用組別，列出姓名非空白、未臨時不打、不在場上的成員 → { member, groupId, groupType, isFixedPair }。rotate 組兩位都會列入，由分數決定誰代表。
3. 產生某場地建議名單前，先 freeCourt 釋出該場地四個座位（其他場地保持占用）。
4. 四人組合合法條件：
   - 非 fixed 組：同組最多一人。
   - fixed 組：只要有其中一人，兩人都必須在這四人中。
5. 列舉全部 C(n,4) 組合（20 人時 4,845 組），每組再檢查三種拆分；不截斷名單。
6. startAll 依序對每個開放場地 proposeCourt，每次選出的人立即入座（onCourt 設定），後續場地自然排除。

五、分數計算（規則與加減分總表見 requirements ALG-04～ALG-07、ALG-09）

pairing.js 頂部常數：

var SCORE = {
  MUCH_BELOW_AVERAGE: 4,
  BELOW_AVERAGE: 2,
  ABOVE_AVERAGE: -2,
  MUCH_ABOVE_AVERAGE: -4,
  RECENT_FINISH_PENALTY: -3,
  RECENT_FINISH_MS: 120000,
  REJECTED_PERSON_PENALTY: -100,
  ALL_FEMALE_BONUS: 2,
  MIXED_DOUBLE_BONUS: 1,
  SKILL_DIFF_0_OR_1: 0,
  SKILL_DIFF_2: -2,
  SKILL_DIFF_3_OR_MORE: -5,
  REST_CREDIT_STEP: 0.5,
  REST_CREDIT_PER_STEP: 0.5,
  MIN_REST_AVERAGE_BASELINE: 1,
  MANUAL_PRIORITY_STEP: 0.5        // 統計區「↑」「↓」每次調整的不打場數
};

1. 個人分數 individualScore(member, state, avgEff, now)

  count = effectivePlayCount(member, state)
  if (count < avgEff - 1)        fairness = +4
  else if (count < avgEff - 0.5) fairness = +2
  else if (count > avgEff + 1)   fairness = -4
  else if (count > avgEff + 0.5) fairness = -2
  else                           fairness = 0
  recentlyFinished = lastFinishedAt != null && 0 <= now - lastFinishedAt < 120000
  return fairness + (recentlyFinished ? -3 : 0)

  邊界：count == avg-1 → +2；count == avg-0.5 → 0；count == avg+0.5 → 0；count == avg+1 → -2。

2. 不打場數

  activeRestCredit(member, avgActual, enabled):
    if (!enabled || !member.resting || member.restStartAverage == null) return 0
    baseline = max(restStartAverage, 1)
    steps = floor((max(0, avgActual - baseline) + 1e-9) / 0.5)
    return steps * 0.5

  setResting(state, id, true)：先設 resting=true，開關開啟時 restStartAverage = max(avgActualPlayCount, 1)（此時本人已不計入平均）；開關關閉時為 null。
  setResting(state, id, false)：開關開啟且有基準時，把 activeRestCredit 加到 restCreditTotal；restStartAverage=null、resting=false。
  setRestCompensationEnabled(false)：對仍在休息且有基準者，結算 activeRestCredit 到 restCreditTotal，基準設 null。
  setRestCompensationEnabled(true)：對仍在休息且無基準者，建立新基準 max(avgActualPlayCount, 1)。

  新人起始補償：Roster.addGroup、Roster.addMemberToGroup、applyImport(update) 的新成員，在開關開啟時 restCreditTotal = Math.round(avgEffectivePlayCount(state) × 2) / 2；否則 0。

3. 配隊分數

  三種分隊（PAIRINGS）：[0,1] vs [2,3]、[0,2] vs [1,3]、[0,3] vs [1,2]。
  genderBonusForSplit：
    - 任一人性別未知 → 0
    - 四人皆 F → +2
    - 2M+2F 且兩隊各為一男一女 → +1
    - 其他 → 0
  skillPenaltyForSplit：四人 skill 皆為 1/2/3 才計算；diff = |teamA 實力和 - teamB 實力和|；diff<=1 → 0；diff==2 → -2；diff>=3 → -5；否則 0。
  pairingScore = genderBonus + skillPenalty。

4. 候選總分與選擇 pickBestCourtCombo(state, now, rng, rejectedIds)

  for 每個合法四人組合：
    sumInd = Σ individualScore(四人)
    for 每種拆分（allSplitsForFour）：
      若含 fixed 組，該組兩人須在同一隊（seatMembers 前兩位為一隊、後兩位為另一隊），否則略過
      rejectedPenalty = 四人中在 rejectedIds 內的人數 × (-100)
      total = sumInd + pairingScore + rejectedPenalty
  保留 total 最高的所有（組合＋拆分）候選；可用人數 < 4 或沒有合法候選時回傳 null。
  同分選擇：程式對同分候選計算 exp((score - best) / 1.5) 權重後抽樣；因只有同分候選，權重皆為 1，等同均勻隨機（K-10）。
  回傳 { persons, people, seatMembers, pairingScore, split, score }，seatMembers 依 teamA 兩位接 teamB 兩位排列，直接對應座位 1、2 vs 3、4。

5. 補位（pickBestCourtCombo 回傳 null 時，proposeCourt / regenerateCourt）

  - 先找出可用人員中的 fixed 組成對成員，依序放入座位 (0,1)、(2,3)。
  - 再依 collectAvailablePersons 順序補入尚未使用的組別與成員。
  - 補不到人則座位為 null；pending 仍設為 true，空位顯示選人面板。

六、場次事件

- startAll：清空 pendingRejectedMemberIds；對每個開放場地 proposeCourt；started=true。
- proposeCourt(court)：以 pickBestCourtCombo（不帶暫時扣分）或補位填入四個座位（commit=false，不計次）；pending[court]=true。
- regenerateCourt(court)（「再換另一批」）：把目前座位成員加入 pendingRejectedMemberIds（不重複）→ freeCourt → pickBestCourtCombo(…, rejectedIds) 或補位 → pending=true。
- confirmCourt(court)（「確認，開始打」，僅 pending 且四位皆滿時可按）：每位入座成員 playCount+1；涉及的每個組別 groupCounts 各 +1（固定組只算一次）；pending=false；清空 pendingRejectedMemberIds。
- 完賽（pending=false 時按「完賽，換下一組」）：該場每位入座成員 lastFinishedAt = Date.now() → refillCourt（freeCourt + proposeCourt）。新建議會立即套用剛下場者的 -3 分。pending=true 時按鈕是「確認，開始打」，不寫 lastFinishedAt。
- 手動換人 assignSeat(court, idx, member, commit)：舊座位成員 onCourt=null；新成員入座。commit = 場地非 pending，此時新成員 playCount+1、groupCounts+1；被換下者不扣回。
- setCourtCount(n)：關閉的場地 freeCourt；已開始時新開的場地 proposeCourt。
- resetCounts（「重置次數」）：所有成員 playCount=0、restCreditTotal=0、lastFinishedAt=null、onCourt=null；仍 resting 者 restStartAverage=1，其餘 null；groupCounts 全 0；courts 清空；pending 全 false；pendingRejectedMemberIds 清空；started=false。保留名單、profiles、gender、skill、courtCount、settings。
- 刪除成員/組別或清空姓名後：clearSeatsFor 清掉相關座位；removeMember 後只剩一人的組別改為 single；接著 refillEmptySeatsIfStarted。
- refillEmptySeatsIfStarted()（未開始時不做事），對每個開放場地：
    四位皆滿 → 略過；
    全空 → proposeCourt（產生待確認名單，pending=true）；
    部分空位 → 對每個空位 Pairing.pickFillCandidate(state, court, idx) 取人，assignSeat(…, commit = !pending[court])；找不到人則保留空位。
  呼叫時機：刪除成員/組別、姓名清空、applyImport 成功後。
- 每個操作結束後 save() 並 render()。

七、手動換人候選推薦 scoredManualCandidates(state, court, seatIndex)（規則見 requirements ALG-08）

- 隊友 = 同隊另一座位（0↔1、2↔3），對手 = 另一隊兩座位；分隊不重排。
- 候選：可用組別中（排除被換下者所屬組別）姓名非空白、未臨時不打、不在場上的每位成員（rotate 組兩人都列入）。未處理 fixed 組限制（K-04）。
- pairing：隊友與兩位對手都有人時，以「隊友＋候選 vs 對手兩人」計算性別加分與實力扣分；否則 0。
- individual：individualScore(候選, state, avgEffectivePlayCount, now)。
- total = individual + pairing；依 total 由高到低，同分依姓名 localeCompare("zh-Hant")。
- pickFillCandidate(state, court, seatIndex)：自動補位用，取 scoredManualCandidates 中排除 fixed 組成員後的第一名；沒有則回傳 null。
- UI：面板頂端「系統換人」直接採用第一名；接著目前人選（標「目前」）；其餘候選顯示性別、實力、「已上 N 次」，pairing > 0 時顯示「★男女配對」（K-05）。

1. 統計 UI（renderStats，僅在 started 時顯示）

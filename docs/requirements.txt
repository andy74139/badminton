羽球輪替板｜需求文件 Requirements
版本：Draft 1.2（2026-10-28）
用途：描述現有功能、行為規則與驗收條件，供 AI 開發時遵循。
注意：這是產品需求文件，不是 Python 套件依賴清單。本版內容以目前 index.html / roster.js / pairing.js 的實際行為為準；程式與預期不一致、尚待修正之處統一列在「七、已知問題」。分數常數屬建議起始值，集中在 pairing.js 的 SCORE 物件管理並方便調整。
閱讀建議：配隊怎麼選人、怎麼加減分，全部集中在「三、配隊演算法」；其他章節只引用，不重複說明。

一、專案目標

改善約 15–20 人、男生通常多於女生的羽球雙打輪替流程。配隊兼顧個人上場公平性、剛下場休息時間、兩隊實力差距，以及性別組合偏好。避免因「女生優先」的硬性排序，導致女生經常被安排上場。

保留純前端、免登入、手機友善使用方式。資料保存在目前裝置的瀏覽器，不新增後端服務或外部資料庫。

二、既有功能（重構後仍須保留）

REQ-EX-01 場地數：可選擇開放 1、2 或 3 個場地（A／B／C）。減少場地時釋出被關閉場地的座位；已開始後增加場地時，新開的場地立即產生建議名單。
REQ-EX-02 雙打安排：每個場地以四個位置組成兩隊對打，位置順序為 1、2 對 3、4。
REQ-EX-03 名單管理（「管理名單」面板）：
  1. 「+ 新增單人」：新增一個單人組（姓名空白，游標自動聚焦）。
  2. 「+ 新增雙人組」：新增一個「雙人輪流」組，含兩個空白名額。
  3. 連結：單人組下方可從下拉選單選另一位單人組成員，並選擇類型「雙人組」（固定雙人組，預設）或「雙人輪流」，按「連結」後兩人併為同一組，被併入者原本的組別刪除。
  4. 分開：雙人組（固定或輪流）可按「分開」拆成兩個單人組，第二位成員移到新組別，新組別沿用原組別的組別輪替次數。
  4-1. 切換類型：雙人卡片底部「分開」左側有切換按鈕，雙人組顯示「改成雙人輪流」、雙人輪流顯示「改成雙人組」，按一下即切換成另一種，按鈕顏色為切換後的類型色。
       隨時都可以切換。
  4-2. 雙人組合變更不影響場上：切換類型、連結、分開隨時都可以做，包括成員正在場上（含待確認名單）時。目前場上的配隊與座位一律保留不動，
       新組合只影響之後的選人：例如兩人都在場上時改成雙人輪流，兩人照常打完；之後兩人都下場，才依「輪流、同時一人」安排。
       某位成員還在場上時，同組另一人也暫時不會被安排（ALG-02 第 4 點）。
  4-3. 次數顯示：單人卡片在右上角顯示「實際 N 次」；雙人卡片改為每人在自己那一行顯示「實際 N 次」（不再合併成「實際 a/b 次」）。
  5. 編輯姓名（最多 12 字）；離開欄位時若姓名為空白，即刪除該成員。
  6. 設定性別、實力（再點一次已選的選項可取消為未設定）。
  7. 雙人組可用「×」移除其中一人，剩下的人改為單人組；整組可用「刪除」移除（需在約 2.6 秒內再按一次「確定？」）。
  8. 版面：姓名輸入框寬度約五個中文字。名單以格線排列，每組一張卡片：平板橫向（約 1024～1200px 寬）3 欄、平板直向 2 欄、手機 1 欄；平板寬度下面板放寬（最寬 1200px）並幾乎佔滿螢幕高度，「實際 N 次」與「刪除」放在卡片右上角。
  9. 三個區塊（由上到下，各有標題與人數／組數）：
      a. 雙人組・雙人輪流（通常 0～3 組）：固定雙人組與雙人輪流的卡片。沒有時顯示提示，說明可在單人卡片「連結」組成。
      b. 單人（通常 12～20 人）：單人組卡片。
      c. 過去名單：瀏覽器人員設定檔（REQ-01）中有、但目前名單沒有的人，依姓名排序，每人一顆按鈕（姓名＋性別／實力）。
         點一下即以單人組加入目前名單，帶入設定檔的姓名、性別、實力；本場統計比照「+ 新增單人」（實際上場 0，不打場數依 ALG-09 新人起始補償）。加入後該人從過去名單移到單人區塊。
         每顆按鈕右側有「×」刪除鈕：第一次點變成紅色「確定刪除？」，約 2.6 秒內再點一次才刪除該人的設定檔，逾時恢復為「×」，避免誤按。刪除後該人不再出現在過去名單，之後再匯入同名者也不會自動帶入舊的性別／實力。目前名單中的人不會出現在過去名單，也不能被刪。
      a、b 兩區內各自維持原本名單順序；連結後的新雙人組移到 a 區，分開後的兩人移到 b 區。此排序只影響名單畫面，不改變資料中的組別順序（補位時的「名單順序」不受影響）。
  10. 雙人類型標示：每張雙人卡片最上方顯示徽章，並在卡片左緣加上同色色條：
      - 雙人組（fixed）：橘色，連結圖示＋「雙人組・同隊上場」。
      - 雙人輪流（rotate）：藍色，輪替箭頭圖示＋「雙人輪流・共用名額」。
      單人組不顯示徽章。缺少 type 的舊資料雙人組行為等同輪流，也標成雙人輪流，並可「分開」。
      場上座位的搭檔標籤「與 X 同隊」「與 X 輪流」使用相同顏色與圖示。
REQ-EX-04 組別類型：每個組別有 type，共三種：single 單人組、rotate 雙人輪流、fixed 固定雙人組。各類型在配隊時的限制見 ALG-03。
REQ-EX-05 性別與實力：性別可為男、女或未設定；實力可為新手、一般、高手或未設定。
REQ-EX-06 建議名單與確認：按「開始」或完賽後自動排出建議名單（待確認名單）。使用者可手動替換個別位置、或按「再換另一批」重新產生。只有按下「確認，開始打」才算正式開始；未確認的建議名單不得增加實際上場次數。待確認名單有空位時，該位置直接顯示選人面板；未滿四人時「確認，開始打」按鈕停用。
REQ-EX-07 完賽輪替：正式場次進行中，按下「完賽，換下一組」會先記錄該場四人的下場時間，再釋出該場地並產生下一組建議名單。其他場地正在打球（含待確認）的人不得被安排到新組合。
REQ-EX-08 手動換人：點座位右上角換人圖示，可只替換該位置而不重排其他三個位置。選人面板順序：「系統換人」、目前人選（標示「目前」）、其他候選（排序見 ALG-08）。
  - 待確認名單中換人：不計次。
  - 已確認（進行中）的場地換人：新入場者立即 +1 實際上場次數及組別輪替次數；被換下者已計的次數不扣回。
REQ-EX-09 臨時不打：可在「休息區」名單的人名旁、或管理名單中按「臨時不打」，將人員排除在自動選人之外；臨時不打的人顯示在「臨時不打」區塊，按「恢復」即重新加入輪替，保留既有資料與統計。
REQ-EX-10 統計與重置：顯示輪替統計；「重置次數」（需二次確認）清空本場統計及場地安排並回到「尚未開始」，但不刪除目前名單、人員設定檔、性別/實力、場地數及補償開關。
REQ-EX-11 本機儲存：資料透過瀏覽器 localStorage 儲存，不依賴 Cookie 或伺服器資料庫。重整頁面後還原已儲存的狀態；儲存失敗時畫面底部顯示錯誤提示。
REQ-EX-12 介面：保留繁體中文、響應式版面、深色模式適應及主要操作流程；除非新功能需要，不重做整體視覺設計。主要使用情境為平板橫向，手機仍須可用。主頁面最寬 1240px（原 900px），平板橫向開 3 個場地時每場約 320～390px 寬；寬度 720px 以下場地改為上下排列。場地卡片在四人皆滿且實際分隊符合時顯示「全女生」或「男女配對」標籤。
REQ-EX-13 自動補位：已開始時，刪除人員／組別、清空姓名，或以「更新目前場次」匯入後，場上出現的空位立即自動補人（選人方式見 ALG-01、ALG-08）。待確認名單的補位不計次；進行中場地補入的人視同手動換人入場，立即 +1 實際上場次數。

三、配隊演算法（選人與加減分的唯一說明處）

ALG-01 什麼時候會選人
  系統有兩種選人方式：

  A. 整場選四人（ALG-02 ～ ALG-07）
     - 按「開始」：依序為每個開放場地選人。
     - 按「完賽，換下一組」：先記錄這四人的下場時間，再為該場地重選。
     - 按「再換另一批」：目前這批人加入暫時扣分名單，再為該場地重選。
     - 已開始後增加場地數：為新開的場地選人。
     - 自動補位時整個場地都空了。
     結果一律是「待確認名單」，按「確認，開始打」才計入上場次數。

  B. 單一位置選人（ALG-08）
     - 手動換人面板的候選排序、「系統換人」。
     - 自動補位時只缺部分位置。
     其他三個座位與分隊不動，只挑一個人補進來。

ALG-02 誰可以被選（候選資格）
  一個人必須同時符合：
  1. 姓名非空白。
  2. 沒有標記臨時不打。
  3. 不在任何場地上（含其他場地的待確認名單）。
  4. 同組的其他成員也不在任何場地上（同組不能跨場）。
  5. 若是固定雙人組：兩人都要符合 1～3，否則整組都不能被選。
  雙人輪流組兩人若都符合，兩人都會列入候選，由分數決定這次誰代表該組上場。
  整場選人時，先釋出該場地原本的四個座位；其他場地的人仍視為在場上。

ALG-03 合法的四人組合（依組別類型）
  - single 單人組：一人。
  - rotate 雙人輪流：同一組最多一人在這四人中。
  - fixed 固定雙人組：只要有其中一人，另一人也必須在這四人中，而且兩人必須在同一隊。
  - 同一人、同一組不能同時出現在兩個場地。
  在 15–20 人規模下，列舉所有可用人員的四人組合（20 人約 4,845 組），不依名單順序截斷。

ALG-04 名詞：場數
  - 實際上場次數：確認開打（或進行中場地換人入場）才 +1；待確認名單不計。
  - 不打場數：補償臨時不打期間沒打到的場數，計算方式見 ALG-09。不是真的打過球。
  - 有效場數 = 實際上場次數 + 不打場數。
    「臨時不打場數」開關關閉時，有效場數 = 實際上場次數（已取得的不打場數保留在資料中，只是不計入）。
  - 平均有效場數：本場名單中「姓名非空白、且未臨時不打」的人（含正在場上的人）有效場數平均。用於公平分數。
  - 平均實際上場次數：同一群人的實際上場次數平均（不含不打場數）。只用於不打場數計算。

ALG-05 總分公式與加減分總表
  整場選人時，每個候選 =「一組四人」＋「一種分隊方式」（四人共有三種分法：12 vs 34、13 vs 24、14 vs 23），分別計分：

    候選總分 = 四人的個人分數總和 + 該分隊的配隊分 + 該分隊的實力分 + 暫時扣分
    配隊分：優先安排「全女生」與「男女配隊（男+女 vs 男+女）」兩種組合。

  加減分總表（常數名稱為 pairing.js 的 SCORE）：

  項目          ｜計分對象｜條件                                              ｜分數 ｜常數
  ──────────────┼────────┼──────────────────────────────────────────────────┼─────┼───────────────────────
  場數遠低於平均 ｜每人    ｜有效場數 < 平均有效場數 − 1                         ｜ +4  ｜MUCH_BELOW_AVERAGE
  場數低於平均   ｜每人    ｜否則，有效場數 < 平均有效場數 − 0.5                 ｜ +2  ｜BELOW_AVERAGE
  場數遠高於平均 ｜每人    ｜否則，有效場數 > 平均有效場數 + 1                   ｜ −4  ｜MUCH_ABOVE_AVERAGE
  場數高於平均   ｜每人    ｜否則，有效場數 > 平均有效場數 + 0.5                 ｜ −2  ｜ABOVE_AVERAGE
  場數接近平均   ｜每人    ｜其他情況                                            ｜  0  ｜—
  剛下場         ｜每人    ｜距離最近一次「完賽，換下一組」未滿 120 秒            ｜ −3  ｜RECENT_FINISH_PENALTY / RECENT_FINISH_MS
  配隊分：全女生 ｜分隊    ｜四人性別皆為女（任何分法都成立）                    ｜ +2  ｜ALL_FEMALE_BONUS
  配隊分：男女配隊｜分隊   ｜四人性別皆已設定、兩男兩女，且兩隊各為男+女          ｜ +1  ｜MIXED_DOUBLE_BONUS
  實力差 0–1     ｜分隊    ｜四人實力皆已設定，兩隊實力和相差 0 或 1             ｜  0  ｜SKILL_DIFF_0_OR_1
  實力差 2       ｜分隊    ｜同上，相差 2                                        ｜ −2  ｜SKILL_DIFF_2
  實力差 ≥3      ｜分隊    ｜同上，相差 3 以上                                   ｜ −5  ｜SKILL_DIFF_3_OR_MORE
  暫時扣分       ｜每人    ｜在「再換另一批」的暫時扣分名單中                    ｜−100 ｜REJECTED_PERSON_PENALTY

  補充規則：
  1. 公平分數五個區間必須依表格由上到下用 if / else if 判斷，邊界一律「嚴格小於／大於」：
     差 −1 剛好 → +2；差 −0.5 剛好 → 0；差 +0.5 剛好 → 0；差 +1 剛好 → −2。
  2. 剛下場：未滿 120,000 ms 扣分（119,999 ms 扣），滿 120,000 ms 不扣。時間只由「完賽，換下一組」按鈕記錄。
  3. 配隊分：任何一人性別未設定 → 0。兩男兩女但分隊是「兩男 vs 兩女」→ 0。其他性別組合（例如三男一女）→ 0。
  4. 實力：新手=1、一般=2、高手=3。任何一人實力未設定 → 實力分 0（不當作 0 或自行猜測）。
  5. 個人分數只看「這個人」，配隊分與實力分只看「這四人怎麼分隊」，全部直接相加；配隊分是軟性優先，不做硬性排序。
  6. 量級參考：一位場數遠低於平均的人（+4）比全女生（+2）影響更大；實力差 ≥3（−5）大約抵銷一位遠低於平均者的優先。暫時扣分（−100）大到幾乎一定換人，但沒有其他合法組合時仍可能選回同一批。

ALG-06 選出結果：分層隨機
  1. 抽籤單位是「四人組合」：每組四人只用自己總分最高的分法參加；同一組四人有多種同分最佳分法時，選中後再均分抽一種。
     （較差的分法不會被抽到，同一組四人也不會因分法多而被重複計算機率。）
  2. 設最高分為 x。總分 x、x−1、x−2 的四人組合可以被抽到，x−3 以下不抽。
     每組權重：x 為 10、x−1 為 3、x−2 為 1（SCORE.RANDOM_TIER_WEIGHTS）。
  3. 防稀釋上限（只壓低下層，不抬高；SCORE.RANDOM_LOWEST_MAX_SHARE_OF_LOWER、RANDOM_LOWER_MAX_SHARE）：
     a. x−1 層有隊伍時，x−2 層最多佔下兩層（x−1 + x−2）合計的 1/4。
     b. 下兩層合計最多佔全部的 1/3，也就是 x 層至少 2/3；超過時下兩層等比例縮小。
     兩個上限都觸發時，三層機率正好是 2/3 : 1/4 : 1/12。
  4. 先依各層總機率抽層，再在層內均分抽一組（只用一個隨機數）。
  5. 不變式：任何一組較高分隊伍的機率 ≥ 任何一組較低分隊伍的機率。
  6. 範圍 2 分 < 剛下場扣分 3 分，所以剛下場的人不會因隨機勝過條件相同、沒剛下場的人。日後若加大範圍，要一起檢查。
  7. 開關：管理名單面板的「分層隨機」設定（預設開啟，settings.tieredRandomEnabled）。關閉時只在最高分 x 的四人組合中均分隨機（每組 1 / x 層組數），x−1、x−2 不抽。
     整場選人、系統換人、自動補位都依此設定；切換只影響之後的選人，已排好的名單不重排。「開始新場次」匯入保留此設定。
  範例（四人組合數 x/x−1/x−2 → 各層總機率；括號內為每組機率）：
     1/1/0 → 77%（77%）/ 23%（23%）
     2/5/30 → 66.7%（33.3%）/ 25%（5%）/ 8.3%（0.28%）
     1/1/100 → 71%（71%）/ 21%（21%）/ 7%（0.07%）
     10/1/0 → 97%（9.7%）/ 2.9%（2.9%）
     1/20/0 → 66.7%（66.7%）/ 33.3%（1.7%）
  3. 座位：第一隊兩人坐位置 1、2，第二隊兩人坐位置 3、4。
  4. 多個場地依序選人，前一場地選中的人立刻視為在場上，後面的場地不會再選到。

ALG-07 找不到合法四人組合時（補位）
  可用人員不足或湊不出合法組合時，不使用分數：
  1. 先把可用的固定雙人組兩人放在同一隊的相鄰座位（1、2 或 3、4）。
  2. 再依名單順序補入其他組別的可用人員，不重複同組或同一人。
  3. 補不滿就保留空位，不重複安排湊數。

ALG-08 單一位置選人（系統換人、部分空位補位、手動換人排序）
  與整場選人用同一套配隊演算法，只是另外三個座位與分隊固定不動、只換這一個位置：
    換入後四人總分 = 另外三位的個人分 + 候選的個人分 + 配隊分 + 實力分
    （個人分 = ALG-05「每人」項目，不含暫時扣分；配隊分、實力分以「隊友＋候選 vs 兩位對手」計算，其他三個座位有空位時兩者為 0。）
  1. 候選資格同 ALG-02；被換下者所屬的組別不列入候選。
  2. 「系統換人」與自動補位：以換入後總分做與 ALG-06 相同的分層隨機（x、x−1、x−2 依 10:3:1，含防稀釋上限），抽籤單位是人。
     固定雙人組成員不列入（只換一個位置無法讓兩人一起上場）；沒有可換入的人時不顯示「系統換人」。
  3. 手動換人面板的候選依換入後分數由高到低排序，同分依姓名（繁體中文排序），所有合法候選（含固定組成員）都列出供人工選擇。
  4. 手動換人面板目前未處理固定雙人組限制，見 K-04。

ALG-09 不打場數（臨時不打補償）怎麼算
  目的：臨時不打的人回來後，不會因為場數落後太多而被連續排上場，也不會因此被永遠排在後面。
  1. 進入臨時不打時，記下「基準」= 當下平均實際上場次數（本人已不計入），小於 1 時取 1。
  2. 臨時不打期間，平均實際上場次數每比基準多出完整的 0.5，就得到 0.5 不打場數。
     例：基準 1.0，平均 1.49 → 0；1.5 → 0.5；1.99 → 0.5；2.0 → 1.0。
  3. 計算平均只用實際上場次數，不加不打場數，避免補償推高平均、再產生更多補償。
  4. 生命週期：
     事件                          ｜處理
     ──────────────────────────────┼──────────────────────────────────────────────────────
     進入臨時不打（開關開）        ｜建立基準（第 1 點）
     進入臨時不打（開關關）        ｜不建立基準，不累積
     恢復上場                      ｜本期已達成的補償加入「已結算不打場數」，清除基準
     關閉開關                      ｜休息中的人先結算本期補償，清除基準；之後不再累積
     開啟開關                      ｜仍在休息的人以當下平均建立新基準，不追溯關閉期間
     重置次數                      ｜實際上場、不打場數歸零；仍在休息的人基準設為 1
     新增成員／更新匯入的新成員    ｜開關開啟時，已結算不打場數起始 = 平均有效場數四捨五入到 0.5；開關關閉時為 0
     開始新場次匯入                ｜全部歸零
     統計區按「↑」／「↓」         ｜不打場數 −0.5／+0.5，最低 0（第 7 點）
  5. 有效場數中的不打場數 = 已結算不打場數 + 目前這段休息期間已達成的補償（開關開啟時）。
  6. 開關只影響補償的累積與計入；被標記臨時不打的人無論開關如何都不會被選人（ALG-02）。
  7. 手動調整優先度（統計區「↑」「↓」）：
     - 「↑」提高優先度：不打場數 −0.5，有效場數變低，公平分數變高。
     - 「↓」降低優先度：不打場數 +0.5，有效場數變高，公平分數變低。
     - 不打場數（已結算＋目前休息期間已達成的補償）不能低於 0；為 0 時「↑」停用。
     - 系統自動給的不打場數（臨時不打補償、新人起始補償）也可以用「↑」一路扣到 0。
       休息中的人按「↑」時，先把本期已達成的補償併入已結算，再扣除；基準跟著後移，保留尚未滿 0.5 的進度，之後照常累積。
     - 載入資料時，若已結算不打場數為負數（舊版手動調整造成）一律改為 0。
     - 開關關閉時不打場數不計入有效場數，兩個按鈕都停用。
     - 每次調整立即儲存並重新計算；已經排好的建議名單不會自動重排。
     - 每按一次的調整量為 SCORE.MANUAL_PRIORITY_STEP（0.5）。

ALG-10 計算範例
  假設平均有效場數 = 3.0，候選四人：
    甲：女、一般(2)、有效 1.8          → 1.8 < 2.0          → +4
    乙：女、高手(3)、有效 2.4          → 2.4 < 2.5          → +2
    丙：男、一般(2)、有效 3.0          → 接近平均           →  0
    丁：男、新手(1)、有效 3.0、60 秒前剛下場 → 0 − 3        → −3
    個人分數總和 = 4 + 2 + 0 − 3 = 3

  三種分法：
    甲乙 vs 丙丁：兩女 vs 兩男 → 配隊分 0；實力 5 vs 3 差 2 → 實力分 −2；總分 3 + 0 − 2 = 1
    甲丙 vs 乙丁：男+女 vs 男+女 → 配隊分 +1；實力 4 vs 4 差 0 → 實力分 0；總分 3 + 1 + 0 = 4  ← 最高
    甲丁 vs 乙丙：男+女 vs 男+女 → 配隊分 +1；實力 3 vs 5 差 2 → 實力分 −2；總分 3 + 1 − 2 = 2

  這四人以最佳分法「甲丙 vs 乙丁」（總分 4）參加抽籤，座位 1 甲、2 丙、3 乙、4 丁；另外兩種分法不參加。
  系統再依所有四人組合的總分做分層隨機（ALG-06）：若全場最高分是 4，這組在 x 層；若最高分是 5 或 6，這組在 x−1 或 x−2 層；最高分 7 以上則抽不到。
  若按過「再換另一批」使這四人都在暫時扣分名單中，總分變為 4 − 400 = −396。

ALG-11 配隊 log（了解運作與除錯）
  每次選人都在瀏覽器開發者工具的 Console 印出一筆可展開的紀錄（標題以「[配隊]」開頭）：
  A. 整場選四人（ALG-01 A 的每個時機，標題註明原因：開始、完賽，換下一組、再換另一批、增加場地、自動補位）
     - 標題：場地、原因、選出的兩隊、總分與所在層、被選中的機率、最高分與同分組數。
     - 分層摘要：各層的分數、組數、總機率與每組機率，防稀釋上限是否觸發，抽到的隨機數；選中的四人有多種同分分法時一併註明。
     - 摘要：評估的候選數與四人組合數、平均有效場數、平均實際上場、臨時不打場數開關。
     - 候選表：依總分排序的前 30 名（Pairing.DEBUG_TOP_N；選中者若不在其中另附），每列為兩隊名單（每人附個人分）、個人分合計、配隊分、實力分、暫時扣分、總分、層、機率、是否選中。每組四人只列一次（最佳分法）。
     - 球友表：所有可用球友的姓名、類型、性別、實力、實際上場、有效場數、與平均差、公平分、剛下場扣分（含幾秒前下場）、是否在暫時扣分名單、個人分。
     - 機率：依 ALG-06 分層計算，x−3 以下顯示「—」；機率很小時保留兩位有效數字，不顯示成 0%。
     - 找不到合法四人組合而改用補位（ALG-07）時，印出一行說明與可用球友名單。
  B. 單一位置選人（系統換人、部分空位補位）：標題為場地、位置、原因、選出者、換入後總分與所在層、機率、最高分與同分人數；同樣印出分層摘要與隨機數；說明另外三位的個人分合計；表格列出所有候選的有效場數、與平均差、公平分、剛下場、個人分、配隊分、實力分、換入後總分、層、機率、是否選中。
  C. log 內的分數與實際評分使用同一份計算（不另寫一套）。index.html 的 PAIRING_LOG 設為 false 可關閉。

四、新增與調整需求

REQ-01 人員設定檔
1. 以正規化姓名為 key，永久保存在瀏覽器中的人員設定檔包含姓名、性別、實力。
2. 人員暫時不在本次名單、從本次名單移除，或匯入名單時未排到場上，都不刪除其設定檔。只有使用者在「過去名單」明確刪除（REQ-EX-03 第 9 點）時才刪除。
3. 在名單中修改性別、實力，或姓名欄位離開（blur）時，同步更新該姓名的設定檔。
4. 下次匯入同一姓名時，自動帶入先前的性別及實力。
5. 姓名正規化：去除前後空白、Unicode NFKC、合併多餘空白；英文字母不區分大小寫。不得用姓名比對來恢復上一場的上場統計，除非該次匯入選擇「更新目前場次」。
6. 匯入時可手動選擇要套用哪一位既有人員設定，亦可選擇不套用並視為新人。這可處理改名或同名問題。
7. 同名或正規化後重複的姓名不得靜默合併；匯入時視為錯誤並阻止確認。

REQ-02 貼上名單及確認流程
1. 管理名單面板有「貼上名單」入口，開啟後提供多行文字輸入框。
2. 輸入時即時預覽：錯誤訊息、警告訊息、解析出的組數與人數，以及每位人員一個「舊設定」下拉選單。
3. 輸入格式：每行一個輪替組別。
   - 單人組：「王小明」（類型 single）。
   - 雙人輪流：「王小明 / 陳小華」（類型 rotate）。
   - 固定雙人組：在最後一段加上類型標記「[固定]」「(固定)」或「【固定】」，以「/」分隔（例如「王小明 / 陳小華 / [固定]」）。標記不算成員；固定雙人組必須剛好兩位成員，否則報錯。
   - 忽略空白行及姓名前後空白；分隔符號固定為斜線「/」。
   - 匯入對話框的說明文字與輸入框範例須包含上述三種寫法。
4. 每位匯入人員的舊設定下拉選單列出全部既有設定檔（顯示姓名、性別、實力），預設為正規化姓名自動匹配的設定，沒有匹配時預設「不套用舊設定」。
5. 確認前不修改目前正式名單、統計或場上安排；按下「確認匯入」後才一次套用；按「取消」或點背景關閉不做任何修改。
6. 匯入模式（單選，預設「開始新場次」）：
   - 開始新場次：採用匯入名單；保留人員設定檔、場地數與補償開關；所有人實際上場次數、不打場數、下場時間、臨時不打狀態、場地安排、待確認狀態、組別輪替次數全部歸零／清除，回到「尚未開始」。
   - 更新目前場次：姓名（正規化後）對應到目前場次既有人員時，保留其實際上場次數、不打場數、下場時間與臨時不打狀態，並套用所選設定的性別/實力；新加入者實際上場次數為 0，不打場數起始值見 ALG-09；被移除的人員離開本場名單，但其設定檔保留；所有組別重新編號，組別輪替次數歸零。
     場上座位：仍在名單中的人保留座位（改用新組別 ID）；被移除者的座位清空；組別關係改變不清除座位（REQ-EX-03 第 4-2 點、REQ-06 第 2 點）；每個人的「在場上」狀態必須與座位一致。之後依 REQ-EX-13 自動補位。
7. 若匯入內容不合法（全空白、空姓名、一行超過兩位成員、固定雙人組不是兩人、重複姓名），預覽顯示原因並停用確認按鈕。

REQ-03 個人分數與公平性：併入 ALG-04、ALG-05。
REQ-04 配隊分數：併入 ALG-03、ALG-05、ALG-06。

REQ-05 臨時不打場數開關
1. 管理名單面板有開關「臨時不打場數 (臨時不打的人不補他這段時間沒打到的場數)」，預設開啟。
2. 開關的計算效果與不打場數的完整規則見 ALG-09。

REQ-05-1 分層隨機開關
1. 管理名單面板「臨時不打場數」下方有開關「分層隨機 (最高分 x、x−1、x−2 的隊伍依 10:3:1 抽；關閉時只在最高分中隨機)」，預設開啟。
2. 設定存在本機（重新整理後保留），規則見 ALG-06 第 7 點。

REQ-06 演算法效能與資料一致性
1. 15–20 人規模採用組合列舉（ALG-03），不引入最佳化套件；換組操作須即時完成。
2. 座位一致性（匯入更新、連結、分開與載入資料時檢查）：座位上的人或其組別不存在 → 清空；同一人同時佔兩個座位 → 只保留第一個（依 A、B、C 場地及座位順序）；座位記錄的組別改為該人目前的組別；每位成員的「在場上」狀態依座位重建。組別關係改變造成的「同組多人在場上」「固定組不在同一隊」不清座位，保留目前配隊。載入時執行此檢查，可修復舊版匯入造成「被標記在場上卻沒有座位、永遠排不到」的資料。

REQ-07 程式碼組織
1. 名單、組別類型、人員設定檔、貼上名單解析與匯入、資料遷移邏輯集中於 roster.js。
2. 分數計算、可用人員收集、組合列舉、配隊拆分、最佳候選選擇、單一位置選人、臨時不打狀態切換集中於 pairing.js。
3. index.html 負責 UI、事件與狀態協調（儲存、確認、完賽、重置、場地數、自動補位）。日後調整名單或配隊規則時，應主要修改對應模組。
4. 不新增框架、建置流程或第三方依賴；保留以 file:// 或靜態主機開啟的一般 script 載入方式（window.Roster、window.Pairing 命名空間）。
5. 保留 localStorage 既有資料並做版本遷移（v1 → v2 → v3）。
6. 關鍵分數常數、資料結構與候選資格規則要有繁體中文註解。
7. 修改三、配隊演算法的任何規則或分數時，須同步更新本章與 pairing.js 的 SCORE 常數。

REQ-08 統計顯示
1. 「上場次數統計」區塊固定展開、不可折疊：每位球友一列，由左到右為：
   - 姓名：寬度固定約五個中文字，超過以「…」截斷。
   - 長條：實際上場（主色）與不打場數（另一色）分段顯示。
   - 文字「實際 N / 不打 X.X」，不打場數不得被誤顯示成真的打過球。
   - 「↑」「↓」按鈕：手動提高／降低此人的優先度，規則見 ALG-09 第 7 點。
2. 「詳細統計」為可展開區塊（預設收合），顯示目前時間（每秒更新）及每人：有效場數、實際上場、已結算不打場數、目前不打場數、下場時間、性別/實力。
3. 組別輪替次數（groupCounts）仍保留於資料中，但不作為個人公平分數依據；名單面板每組顯示各成員「實際 N 次」。
4. 手動換人選人面板每位候選顯示性別、實力、「已上 N 次」；換入後會形成全女生顯示「★全女生」、形成男女配隊顯示「★男女配對」。

REQ-09 再換另一批
1. 待確認名單下方顯示「再換另一批」按鈕（場地進行中時隱藏）。
2. 按下後，目前這批人加入「暫時扣分名單」（可重複累加），釋出該場地並重新選人；扣分方式見 ALG-05。
3. 任一場地按「確認，開始打」、按「開始」或「重置次數」時清空暫時扣分名單。

REQ-10 系統換人
1. 選人面板最上方提供「系統換人」：依 ALG-08 第 2 點，以換入後四人總分做分層隨機。每次按都重新計算、重新隨機。

五、驗收條件

AT-01 重新整理頁面後，名單、組別類型、性別、實力、場次、場地安排、設定與不打狀態仍能依最後成功儲存的資料還原。
AT-02 人員從本次名單移除後再度匯入同名者，性別與實力可自動恢復；以「開始新場次」匯入時本場統計不會被帶回。
AT-03 貼上名單後，確認前可預覽與取消；取消不得更動原名單及統計。
AT-04 全女生只有 +2 配隊分，不存在高於個人公平性所需的硬性優先規則；場數相同時，有 4 位可上場的女生就會選出全女生，只有 2 位女生時選出男女配隊。
AT-05 兩男兩女只有在兩隊都各為一男一女時才獲得 +1 分。
AT-06 個人場數分數的所有邊界（平均值差距 -1、-0.5、+0.5、+1）符合 ALG-05；近期下場 119,999 ms 扣分、120,000 ms 不扣分。
AT-07 實力差距 0、1、2、3、4 分別得到 0、0、-2、-5、-5 分；缺資料時不套用實力扣分。
AT-08 平均實際上場次數每個完整 +0.5 門檻，讓目前不打者增加 0.5 不打場數；不打場數不參與平均實際上場次數的計算；臨時不打者不計入平均。
AT-09 關閉補償開關後，不打者仍不會被安排上場；關閉期間不新增補償，已累積補償不消失。
AT-10 任意場地不會重複同一人或同一組；候選評估不會因原始名單超過 12 組而忽略後段球友。
AT-11 建議名單未確認時不增加實際上場次數；完賽事件會記錄當時該場四位球友的下場時間。
AT-12 「重置次數」只重置本場統計與場地狀態，不刪除名單、人員設定檔或性別/實力設定。
AT-13 不引入新框架或不必要依賴，15–20 人時換組操作能即時完成。
AT-14 固定雙人組只會兩人一起、且同隊被自動安排；其中一人臨時不打時整組不被自動安排。
AT-15 補償開關開啟時新增的成員，起始不打場數為當下平均有效場數四捨五入到 0.5。
AT-16 「再換另一批」後，新建議名單在可行時不含前一批的人；確認後暫時扣分清除。
AT-17 貼上「A / B / [固定]」建立固定雙人組；「A / [固定]」報錯。
AT-18 以「更新目前場次」匯入後，留在名單中的人座位不變，被移除者的座位自動補人，且沒有人被卡在「在場上」卻沒有座位。
AT-19 在待確認名單中刪除人員，自動補位不增加任何人的實際上場次數；進行中場地補入的人 +1。
AT-20 ALG-10 計算範例的四人，三種分法總分依序為 1、4、2，選出「甲丙 vs 乙丁」。
AT-21 「上場次數統計」姓名欄寬約五個中文字；手機寬度（375px）下整列含「↑」「↓」按鈕不產生水平捲動。
AT-22 按「↓」不打場數 +0.5、按「↑」−0.5，重新整理後保留；不打場數不低於 0，系統給的不打場數（含休息中累積的補償）可扣到 0；補償開關關閉時兩個按鈕停用。
AT-23 「管理名單」姓名欄約五個中文字寬；1180×820 與 1024×768 顯示 3 欄、820×1180 顯示 2 欄、375px 手機 1 欄，卡片內容不溢出、不互相重疊，頁面無水平捲動。
AT-24 「管理名單」中所有雙人組排在單人組之前，兩段內順序與原名單相同；重新整理後資料中的組別順序不變。
AT-25 「管理名單」每個雙人組卡片顯示正確的類型徽章與色條（雙人組橘色、雙人輪流藍色），淺色與深色模式皆清楚可讀，且徽章不與右上角的次數／刪除重疊。
AT-26 「管理名單」依序顯示「雙人組・雙人輪流」「單人」「過去名單」三個區塊；過去名單只列不在目前名單中的已存設定檔，點一下即以單人加入並帶入性別／實力，且該人從過去名單消失。
AT-27 過去名單按「×」一次只會變成「確定刪除？」，不刪除；約 2.6 秒後恢復；在確認狀態再按一次才刪除，重新整理後該人仍不在過去名單。目前名單中的人無法被刪除設定檔。
AT-28 開 3 個場地時，1180×820 每場約 370px、1024×768 約 320px、1366×1024 約 390px 寬；375px 手機場地上下排列；皆無水平捲動。
AT-29 雙人卡片按切換按鈕可在雙人組與雙人輪流之間來回切換，徽章、色條與按鈕文字同步更新，重新整理後保留；兩人都在場上時也可切換。
AT-30 場上有人時切換類型、連結、分開，三個場地的座位都不變（重新整理後也不變）；該場完賽後，下一組依新組合安排（例如輪流組另一人仍在場上時，下場者暫不被安排）。
AT-31 雙人卡片每人一行顯示自己的「實際 N 次」，不再出現「實際 a/b 次」；單人卡片右上角顯示「實際 N 次」。
AT-32 按開始、完賽、再換另一批、系統換人時，Console 各出現一筆「[配隊]」紀錄，含候選表、球友表與機率；候選總分 = 個人分合計 + 配隊分 + 實力分 + 暫時扣分；同分候選的機率合計 100%。
AT-33 「系統換人」依換入後四人總分分層隨機（ALG-06、ALG-08）；重複按會隨機選到不同的人，Console 顯示每人所在層與機率；固定雙人組成員不會被單獨換入。
AT-34 分層隨機：x、x−1、x−2 每組權重 10:3:1；x 層總機率至少 2/3；x−1 有隊伍時 x−2 最多佔下兩層 1/4；兩上限都觸發時為 2/3 : 1/4 : 1/12；任何一組較高分隊伍的機率 ≥ 較低分隊伍；x−3 以下不會被選；ALG-06 的五個範例數字相符。
AT-35 同一組四人在候選中只出現一次，且以最高分的分法參加；系統換人也依換入後總分分層隨機（較低層也可能被抽到）。
AT-36 關閉「分層隨機」後，整場選人與系統換人只會選到最高分的隊伍／人選，Console 標示「分層隨機：關閉」；重新整理與「開始新場次」匯入後設定保留；預設為開啟。

羽球輪替板｜需求文件 Requirements
版本：Draft 1.0
用途：描述現有功能、這次要改善的行為與驗收條件，供 AI 開發時遵循。
注意：這是產品需求文件，不是 Python 套件依賴清單。若與目前程式實作有差異，以本文件的目標行為為準；分數常數屬建議起始值，應集中管理並方便調整。

一、專案目標

改善約 15–20 人、男生通常多於女生的羽球雙打輪替流程。配隊應兼顧個人上場公平性、剛下場休息時間、兩隊實力差距，以及性別組合偏好。避免因「女生優先」的硬性排序，導致女生經常被安排上場。

保留目前網站的純前端、免登入、手機友善使用方式。資料保存在目前裝置的瀏覽器，不新增後端服務或外部資料庫。

二、既有功能（重構後仍須保留）

REQ-EX-01 場地數：可選擇開放 1、2 或 3 個場地。
REQ-EX-02 雙打安排：每個場地以四個位置組成兩隊對打，位置順序為 1、2 對 3、4。
REQ-EX-03 名單管理：可新增單人、雙人共用名額的組別、編輯姓名、設定性別與實力、刪除人員或組別。
REQ-EX-04 雙人組：同一雙人組共用一個輪替名額；每次上場從這組可出賽的成員中選一人，原則上較少實際上場者優先。不得讓同組兩人同時出現在不同場地。
REQ-EX-05 性別與實力：性別可為男、女或未設定；實力可為新手、一般、高手或未設定。
REQ-EX-06 建議名單與確認：自動排出建議名單後，使用者可以手動替換個別位置。只有按下「確認，開始打」才算正式開始，未確認的建議名單不得增加實際上場次數。
REQ-EX-07 完賽輪替：正式場次進行中，按下「完賽，換下一組」後，釋出該場地並產生下一組建議名單。其他場地正在打球的人不得被安排到新組合。
REQ-EX-08 手動換人：能只替換某個位置而不重排其他三個位置，候選人清單須提供排序或推薦。
REQ-EX-09 臨時不打：可將人員暫時排除在自動選人之外，恢復後保留其既有資料與統計。
REQ-EX-10 統計與重置：顯示輪替統計；「重置次數」清空本場統計及場地安排，但不刪除目前名單和人員設定。
REQ-EX-11 本機儲存：目前資料透過瀏覽器 localStorage 儲存，不依賴 Cookie 或伺服器資料庫。重整頁面後要還原已儲存的狀態。
REQ-EX-12 介面：保留現有繁體中文、響應式版面、深色模式適應及主要操作流程；除非新功能需要，不重做整體視覺設計。

三、新增與調整需求

REQ-01 人員設定檔
1. 以姓名為預設比對依據，永久保存在瀏覽器中的人員設定檔至少包含姓名、性別、實力。
2. 人員暫時不在本次名單、從本次名單移除，或匯入名單時未排到場上，都不能因此刪除其設定檔。
3. 下次匯入同一姓名時，自動帶入先前的性別及實力。
4. 姓名比對前須做正規化：去除前後空白、合併多餘空白；英文字母不區分大小寫。不得用姓名比對來恢復上一場的上場統計，除非該次匯入明確選擇保留同一場次統計。
5. 匯入時可手動選擇要套用哪一位既有人員設定，亦可選擇不套用並視為新人。這可處理改名或同名問題。
6. 同名或正規化後重複的姓名不得靜默合併；確認前需警告並要求修正或手動處理。

REQ-02 貼上名單及確認流程
1. 名單管理新增「貼上名單」入口，提供多行文字輸入框。
2. 預覽及確認前，顯示解析後的人員、組別數、人數、重複姓名及既有設定匹配結果。
3. 輸入格式：每行一個輪替組別。單人組直接輸入「王小明」；共用一個輪替名額的雙人組輸入「王小明 / 陳小華」。允許忽略空白行及姓名前後空白。雙人分隔符號固定為斜線「/」。
4. 每位匯入人員可在確認畫面選擇自動匹配的設定、手動指定舊設定，或不套用舊設定。
5. 確認前不得修改目前正式名單、統計或場上安排。按下確認後才一次套用，避免取消操作留下半套資料。
6. 匯入流程必須明確區分「開始新場次」與「更新目前場次」：
   - 開始新場次：採用匯入名單；保留人員設定檔；清空本場實際上場次數、不打場數次數、下場時間戳、場地安排及待確認狀態；臨時不打狀態預設清除。
   - 更新目前場次：姓名對應到目前場次既有人員時，保留其本場統計；新加入的人員本場統計從 0 開始；被移除的人員離開本場名單，但其設定檔保留；須清除任何已不合法的場上位置，且不得留下無效 memberId。
7. 若匯入內容不合法，需顯示原因並阻止確認，不得以空名或重複 ID 靜默繼續。

REQ-03 個人分數與公平性
1. 每次產生新場次時，評估所有可行的四人組合。總分最高者優先安排。
2. 每個候選組合的總分 = 四位候選人的個人分數總和 + 該四人的最佳配隊分數。
3. 個人有效場數 = 實際上場次數 + 不打場數次數（僅在「臨時不打場數分數」開啟時；關閉時不計算不打場數次數，但已取得的補償資料仍保留）。實際上場次數只在場次確認開始或既有規則認定確實入場時更新；未確認的建議名單不計入。
4. 個人公平分數根據其有效場數與目前名單平均有效場數的差距，以明確的離散區間計分，不使用連續函數。建議起始值：
   - 有效場數 < 平均有效場數 - 1：+4
   - 否則，有效場數 < 平均有效場數 - 0.5：+2
   - 否則，有效場數 > 平均有效場數 + 1：-4
   - 否則，有效場數 > 平均有效場數 + 0.5：-2
   - 其他情況：0
   必須依上述順序用 if / else if 判斷，使區間互不重疊。等於邊界時按照嚴格小於／大於規則處理。
5. 個人近期下場扣分：距離該人最近一次「完賽，換下一組」時刻未滿 120 秒，額外扣 3 分；達到或超過 120 秒即不扣分。時間由按鈕事件記錄，不以頁面重整時間或推測開打時間代替。
6. 最終分數常數集中管理，方便測試後調整；不得在多個檔案散落相同魔法數字。

REQ-04 配隊分數
1. 四位人選需嘗試所有三種兩隊拆分方式，並為每種拆分計算配隊分數。
2. 若四人性別皆明確為女，該四人組合加 +2 分（四女同場）。
3. 若四人性別皆已設定，且是兩男兩女，並且實際分隊為「一男一女 vs 一男一女」，加 +1 分（男女混雙）。若只有兩男兩女但實際拆分並非男女混雙，不得拿此加分。
4. 實力值為新手=1、一般=2、高手=3。四人均有有效實力值時，計算兩隊實力總和之差的絕對值：差距 0–1 時扣 0 分；差距 2 時扣 2 分；差距 >=3 時扣 5 分。
5. 若有任何一人未設定有效實力，該候選拆分不計實力差距扣分；不得把未設定當成 0 或自行猜測。
6. 性別加分是軟性偏好，不得改成無條件硬性排序。個人公平分數及近期下場扣分必須與配隊分數相加比較。
7. 若多個候選組合總分相同，可在最高分候選中隨機選擇，避免名單排序造成固定偏差。

REQ-05 臨時不打場數機制（可關閉）
1. 設定頁新增開關「臨時不打場數分數」。預設開啟；開關關閉只停用不打場數的累積，不得讓被標記為臨時不打的人重新進入選人名單。
2. 每個人在進入臨時不打狀態時，記錄當時所有本場有姓名人員的「平均實際上場次數」作為基準；基準值 <=1 時一律採用 1。
3. 臨時不打期間，平均實際上場次數每高於該基準完整增加 0.5，就增加 0.5 次不打場數。例如基準 1.0，平均實際上場次數到 1.49 時補償為 0，到 1.5 時為 0.5，到 2.0 時為 1.0。
4. 計算上述平均值時只能用實際上場次數，不可把不打場數加入平均值，避免補償額反過來推高平均並造成回饋循環。
5. 不打場數可分次累積。恢復上場時，結算當前不打期間補償並保留總額；再度臨時不打時，以新基準開始新的期間。
6. 個人有效場數 = 實際上場次數 + 已結算不打場數 + 目前仍在不打期間已達成的補償。
7. 關閉此功能時，已取得的補償保留、不再新增補償。若有人當下仍在臨時不打，關閉期間不累積；重新開啟時，該人的新基準從重新開啟當下的平均實際上場次數（若 <=1 則取 1）開始，不追溯關閉期間。
8. 重置本場統計時，實際上場次數及不打場數歸零；若仍標記臨時不打，重新建立基準，不得繼承上一場的基準。

REQ-06 演算法效能與正確性
1. 預設人數約 15–20 人。可採用直觀的 greedy / 組合列舉，不需要引入大型最佳化套件。
2. 必須考慮所有可行候選人組合，不得只取名單前 12 組或依原始名單順序任意截斷候選。
3. 同一雙人組同一時間最多只能派出一人；同一人或同一組不得同時出現在兩個場地。
4. 已在其他場地、姓名空白或標記臨時不打的人不得作為候選人。
5. 若目前可用輪替組別不足四組，應顯示清楚提示、保留空位並避免無限重試或發生例外；不得為了填滿場地重複安排同一組。
6. 產生多個場地的建議名單時，前一場地的候選人必須立刻被視為已保留，後續場地不能再次使用同一組或同一人。

REQ-07 程式碼組織
1. 將名單、人員設定檔、貼上名單解析與匯入相關邏輯集中至 `roster.js`。
2. 將分數計算、可行組合列舉、配隊拆分及最佳候選選擇集中至 `pairing.js`。
3. 保留現有 HTML/UI 與主要操作流程。允許初次重構時更新 HTML 以載入新檔案；日後只調整名單或配隊規則時，應能主要修改對應模組，而不是修改整份 HTML。
4. 不新增框架、建置流程或第三方依賴，除非確有必要並先說明理由。保留目前靜態網站可部署方式。
5. 保留 localStorage 既有資料並做版本遷移。遷移時將現有姓名、性別、實力建立到設定檔；不得因新增欄位而把既有名單或統計直接重設。
6. 關鍵分數常數、資料結構與候選資格規則要有繁體中文註解，易於日後自行調整。

REQ-08 統計顯示
1. 因新演算法以個人為單位，統計介面應至少能查看每位球友的實際上場次數及有效場數；不打場數不可被誤顯示成真的打過球。
2. 若保留原本組別上場次數統計，需清楚標示其為組別輪替次數，不可將其當作個人公平性分數的唯一依據。
3. 候選名單可顯示實際上場次數、有效場數、近期下場扣分與推薦理由，方便現場理解配隊結果。

四、驗收條件

AT-01 重新整理頁面後，名單、性別、實力、場次、場地安排、設定與不打狀態仍能依最後成功儲存的資料還原。
AT-02 人員從本次名單移除後再度匯入同名者，性別與實力可自動恢復；本場統計不得因單純使用舊設定而被錯誤帶回。
AT-03 貼上名單後，確認前可預覽與取消；取消不得更動原名單及統計。
AT-04 四位女生同場最多只有規定的 +2 性別加分，不存在高於個人公平性所需的硬性優先規則。
AT-05 兩男兩女只有在兩隊都各為一男一女時才獲得 +1 分。
AT-06 個人場數分數的所有邊界（平均值差距 -1、-0.5、+0.5、+1）符合本文件明確區間，近期下場的 119,999 ms 扣分、120,000 ms 不扣分。
AT-07 實力差距 0、1、2、3、4 分別得到 0、0、-2、-5、-5 分；缺資料時不套用實力扣分。
AT-08 平均實際上場次數的每個完整 +0.5 門檻，讓目前不打者增加 0.5 不打場數；不打場數不參與自身累積基準平均的計算。
AT-09 關閉補償開關後，不打者仍不會被安排上場；開關期間不新增補償，已累積補償不消失。
AT-10 任意場地不會重複同一人或同一雙人組；候選評估不會因原始名單超過 12 組而忽略後段球友。
AT-11 建議名單未確認時不增加實際上場次數；完賽事件會記錄當時該場四位球友的下場時間。
AT-12 「重置次數」只重置本場統計與場地狀態，不刪除名單、人員設定檔或性別/實力設定。
AT-13 不引入新框架或不必要依賴，且在 15–20 人的常見人數下，換組操作應能即時完成。

五、新增輪替操作需求
- 完賽換組時，除「確認，開始打」外，增加「再換另一批」按鈕；重新產生候選時，目前這批四人獲得暫時扣分，系統換選另一批，讓下一組分數較高者優先；再次點擊時，新的四人獲得暫時扣分。
- 手動換人介面的第一個選項增加「系統換人」，由系統從候選中選擇最適合的人。
- 「上場次數統計」不折疊，維持展開，並顯示實際上場、已結算補償、目前不打場數。
- 「個人統計」改為「詳細統計」，清楚顯示每人各項參數與計算結果。
- 補償開關文字改為「臨時不打場數分數 (臨時不打的人不補他這段時間沒打到的場數)」。
